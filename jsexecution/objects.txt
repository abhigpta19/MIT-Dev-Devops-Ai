

```js
const name = "Abhishek";
const age = 25;
const course = "JavaScript";
const isStudent = true;
```

But now imagine **100 students**.

We would have:

```js
const student1Name = "Rahul";
const student1Age = 20;
const student1Course = "JavaScript";

const student2Name = "Priya";
const student2Age = 21;
const student2Course = "React";
```

This becomes messy.

Instead:

```js
const student = {
    name: "Rahul",
    age: 20,
    course: "JavaScript",
    isStudent: true
};
```

This is an **object**.

### Definition

> **An object is a collection of related data and behavior represented using key-value pairs.**

```js
const student = {
    name: "Rahul",
    age: 20,
    course: "JavaScript"
};
```

Visualize it:

```text
student
   │
   ├── name   → "Rahul"
   ├── age    → 20
   └── course → "JavaScript"
```

# 2. Object = Key + Value

The fundamental structure:

```js
const user = {
    name: "Rahul",
    age: 22
};
```

Here:

```text
key             value
 ↓                ↓
name          → "Rahul"
age           → 22
```

The key is also commonly called a **property name**.

```js
user.name
```

means:

> Find the `name` property inside `user`.

# 4. Properties vs Methods

This distinction is important.

```js
const user = {
    name: "Rahul",
    age: 20,

    greet() {
        console.log("Hello");
    }
};
```

`name` and `age` are **properties**.

`greet` is a **method**.

You can explain:

> A method is essentially a function stored as an object property.

# 5. Accessing Object Properties

## Dot notation

```js
const user = {
    name: "Rahul",
    age: 20
};

console.log(user.name);
console.log(user.age);
```

Output:

```text
Rahul
20
```

---

## Bracket notation

```js
console.log(user["name"]);
console.log(user["age"]);
```

Output:

```text
Rahul
20
```

Then give them the interesting example:

```js
const key = "name";

console.log(user[key]);
```

Output:

```text
Rahul
```

But:

```js
console.log(user.key);
```

Output:

```text
undefined
```

Why?

```js
user.key
```

means:

> Find property literally called `"key"`.

Whereas:

```js
user[key]
```

means:

> Evaluate `key`, get `"name"`, then find `"name"`.

# 13. The Reference Mental Model

Don't simply say:

> Objects are stored in heap.

That's an oversimplification.

Instead teach the useful mental model:

```js
const user1 = {
    name: "Rahul"
};

const user2 = user1;
```

Think:

```text
user1 ────────┐
              ↓
          ┌─────────────┐
          │ name: Rahul │
          └─────────────┘
              ↑
user2 ────────┘
```

Both variables refer to the **same object**.

Therefore:

```js
user2.name = "Aman";
```

changes the same object.

# 14. Equality with Objects

Another excellent demo:

```js
const a = {
    name: "Rahul"
};

const b = {
    name: "Rahul"
};

console.log(a === b);
```

Output:

```text
false
```

Why?

Because these are two different objects.

```text
a → Object #1

b → Object #2
```

Even though their contents are identical.

But:

```js
const a = {
    name: "Rahul"
};

const b = a;

console.log(a === b);
```

Output:

```text
true
```

Because:

```text
a ──┐
    ↓
 Object #1
    ↑
b ──┘
```

# 28. Spread is NOT deep copy

This is extremely important.

```js
const user = {
    name: "Rahul",

    address: {
        city: "Delhi"
    }
};

const copy = {
    ...user
};

copy.address.city = "Mumbai";

console.log(user.address.city);
```

Output:

```text
Mumbai
```

Why?

Because spread only copies the **first level**.

Visual:

```text
user ───────────────┐
                    ↓
             address object
                    ↑
copy ───────────────┘
```

# 29. Shallow Copy

Definition:

> A shallow copy copies the outer object but preserves references to nested objects.

Example:

```js
const original = {
    name: "Rahul",
    address: {
        city: "Delhi"
    }
};

const copy = { ...original };
```

Now:

```text
original ──→ address ←── copy
```

But:

```text
original !== copy
```

while:

```text
original.address === copy.address
```

Demo:

```js
console.log(original === copy);
console.log(original.address === copy.address);
```

Output:

```text
false
true
```

This is a fantastic classroom demo.

---

# 30. Deep Copy

A deep copy means:

> Nested objects are also copied into independent objects.

Modern JavaScript provides:

```js
structuredClone()
```

Example:

```js
const original = {
    name: "Rahul",
    address: {
        city: "Delhi"
    }
};

const copy = structuredClone(original);

copy.address.city = "Mumbai";

console.log(original.address.city);
console.log(copy.address.city);
```

Output:

```text
Delhi
Mumbai
```

Now:

```js
console.log(original.address === copy.address);
```

Output:

```text
false
```

---

# 31. `JSON.parse(JSON.stringify())`

Students will see this old technique everywhere.

```js
const copy = JSON.parse(
    JSON.stringify(original)
);
```

It can work for simple JSON-compatible data.

But it has limitations.

For example:

```js
const obj = {
    date: new Date(),
    value: undefined,
    fn: function () {}
};
```

JSON serialization doesn't preserve all JavaScript types/values correctly.

So teach:

> For general structured data, prefer `structuredClone()` when its supported data types fit your needs.

# The final story I would leave them with

End the class with this:

```text
                 OBJECT
                   │
          collection of properties
                   │
          ┌────────┴────────┐
          ↓                 ↓
        values           functions
          │                 │
       property          method
```

Then:

```text
JavaScript
│
├── Primitive values
│
└── Objects
     │
     ├── Plain objects
     ├── Arrays
     ├── Functions
     ├── Dates
     ├── Maps
     ├── Sets
     └── many built-in objects
```

And the **three rules students absolutely must remember**:

### Rule 1

```js
const a = object;
```

doesn't create a new object.

It creates another reference to the same object.

### Rule 2

```js
const copy = { ...object };
```

creates a **shallow copy**, not a deep copy.

### Rule 3

```js
const { name } = user;
```

is destructuring, while:

```js
const copy = { ...user };
```

is spreading.
