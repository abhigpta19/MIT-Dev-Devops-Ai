DOM
1. What Actually Happens When HTML Loads? — 10 min

Show:

<!DOCTYPE html>
<html>
    <body>
        <h1>Hello</h1>

        <div>
            <p>Welcome</p>
            <button>Click</button>
        </div>
    </body>
</html>

Tell them:

The browser doesn't just "display HTML."

It parses HTML and creates an in-memory tree-like representation.

                document
                   |
                 html
                   |
                 body
              /         \
            h1           div
            |          /    \
          Hello        p    button
                       |       |
                   Welcome    Click

This is the DOM tree.

Important distinction
HTML
 ↓
Browser parses it
 ↓
DOM
 ↓
JavaScript interacts with DOM
 ↓
Browser updates what you see

Don't go deep into browser internals yet.

Just give them this mental model:

HTML is the initial structure. DOM is the browser's live representation of that structure.

2. 🔥 Open DevTools and Actually See the DOM

This should be a major part of the lecture.

Open:

Chrome → DevTools → Console

document

document.body

Then:

Show them that these aren't strings.

They are objects representing HTML elements.

3. The DOM Is LIVE 😮

This is a very cool demonstration.

Suppose:

<h1 id="title">Hello</h1>

Console:

const title = document.querySelector("#title");

title.innerText = "DOM is powerful!";

The page changes immediately.

Then:

title.style.color = "red";

Then:

title.style.fontSize = "60px";

Then:

title.style.backgroundColor = "yellow";

Now ask:

"Did we modify the HTML file?"

No.

We modified the DOM representation.

4. Selecting Elements

Teach only the selectors they'll actually use.

getElementById
document.getElementById("title");
querySelector
document.querySelector("h1");
document.querySelector(".card");
document.querySelector("#title");

And importantly:

document.querySelector(".card button");

CSS selector knowledge directly transfers here.

querySelectorAll
const cards = document.querySelectorAll(".card");

console.log(cards);

Then:

cards.forEach(card => {
    console.log(card);
});
🔥 Important concept

Ask:

document.querySelector(".card")

vs

document.querySelectorAll(".card")

One returns the first matching element.

The other returns all matching elements.

5. Controlling HTML

Now give them the DOM control toolbox.

Change text
element.innerText = "Hello";

and:

element.textContent = "Hello";

Briefly explain:

innerText → visible text
textContent → text content regardless of visual rendering

Don't spend 20 minutes on the distinction.

6. innerHTML — 🔥 First "Power" Concept
const box = document.querySelector(".box");

box.innerHTML = `
    <h2>Hello</h2>
    <p>This was created using JavaScript</p>
`;

Now:

box.innerHTML += `
    <button>Click me</button>
`;



JavaScript isn't limited to changing existing HTML. It can generate HTML.

Then immediately teach the important production warning:

element.innerHTML = userInput;

can become a security problem if untrusted content is inserted.

You don't need to teach XSS deeply today.

Just plant the seed:

innerHTML is powerful, therefore dangerous when used with untrusted input.

That already makes the lecture feel less "beginner tutorial."

7. Attributes

HTML:

<img id="profile" src="cat.jpg">

JavaScript:

const img = document.querySelector("#profile");

img.src = "dog.jpg";

Also:

img.setAttribute("src", "dog.jpg");

Read:

img.getAttribute("src");

Remove:

img.removeAttribute("src");

And:

element.hasAttribute("disabled");
8. Classes — Production-Relevant

Don't teach:

element.style.color = ...
element.style.backgroundColor = ...
element.style.padding = ...

as the primary way of building UI.

Instead introduce:

element.classList

Example:

card.classList.add("active");
card.classList.remove("active");
card.classList.toggle("active");
card.classList.contains("active");

This is a great moment to tell them:

In real applications, JavaScript usually controls state/classes, while CSS controls presentation.

For example:

menu.classList.toggle("open");

CSS:

.menu.open {
    display: block;
}

That is a much more professional mental model.

9. Creating DOM Elements Dynamically

This is where things become interesting.

const card = document.createElement("div");

card.innerText = "I was created using JS";

document.body.appendChild(card);

Then:

const button = document.createElement("button");

button.innerText = "Delete";

card.appendChild(button);

Then:

card.remove();

Teach these:

createElement()
append()
appendChild()
prepend()
remove()

Don't overwhelm them with every DOM method.

12. addEventListener

Start with:

button.addEventListener("click", () => {
    console.log("Button clicked");
});

Then:

button.addEventListener("click", function () {
    console.log("clicked");
});

Explain:

element
   ↓
addEventListener
   ↓
event type
   ↓
callback

Conceptually:

"When this event happens, execute this function."

13. The Event Object 🔥

Now:

button.addEventListener("click", (event) => {
    console.log(event);
});

Open the object.

Show them things like:

event.type
event.target
event.currentTarget
event.clientX
event.clientY

This is where you can make it interesting.

Click anywhere:

document.addEventListener("click", (event) => {
    console.log(event.clientX, event.clientY);
});

Now students can see the mouse coordinates.

14. target vs currentTarget

This is an important professional concept.

HTML:

<div id="parent">
    <button>Click</button>
</div>

JS:

parent.addEventListener("click", (event) => {
    console.log("target:", event.target);
    console.log("currentTarget:", event.currentTarget);
});

Click button.

Explain:

target
→ element where the event originated

currentTarget
→ element whose listener is currently executing

This sets up bubbling perfectly.

15. 🔥 Event Bubbling — Visual Demo

Use:

<div id="grandparent">
    GRANDPARENT

    <div id="parent">
        PARENT

        <button id="child">
            CHILD
        </button>
    </div>
</div>

Attach listeners:

grandparent.addEventListener("click", () => {
    console.log("grandparent");
});

parent.addEventListener("click", () => {
    console.log("parent");
});

child.addEventListener("click", () => {
    console.log("child");
});

Click button.

Output:

child
parent
grandparent

Draw:

          GRANDPARENT
               ↑
             PARENT
               ↑
             BUTTON

Event travels upward.

This is bubbling.
16. Stop Bubbling
child.addEventListener("click", (event) => {
    event.stopPropagation();

    console.log("child");
});

Now:

child

Tell them:

stopPropagation() stops the event from continuing through the propagation path.

But warn them:

Don't randomly use stopPropagation() everywhere. It can break other event logic.

17. Capturing

Now show:

grandparent.addEventListener(
    "click",
    () => console.log("grandparent"),
    true
);

Or preferably explain the third argument:

{
    capture: true
}

Example:

grandparent.addEventListener("click", handler, {
    capture: true
});

Now visualize:

grandparent
     ↓
   parent
     ↓
   button

TARGET

button

BUBBLING

button
  ↑
parent
  ↑
grandparent

Give them the complete mental model:

        CAPTURE
           ↓
Grandparent
           ↓
Parent
           ↓
Button
           ↑
        BUBBLE

That's enough for today.

18. 🔥 Event Delegation

This is where you make them feel:

"Oh... this is actually used in real applications."

HTML:

<ul id="todos">
    <li>Learn DOM</li>
    <li>Learn Events</li>
    <li>Build Project</li>
</ul>

Instead of:

document.querySelectorAll("li").forEach(li => {
    li.addEventListener("click", ...);
});

Do:

todos.addEventListener("click", (event) => {
    if (event.target.tagName === "LI") {
        console.log(event.target.innerText);
    }
});

Explain:

We attach one listener to the parent and use bubbling to handle events from children.

Then show why this is powerful.

Create a new <li> after the listener was registered.

const li = document.createElement("li");
li.innerText = "New Task";

todos.append(li);

Click it.

It still works.

🔥

That's a very strong demonstration.

24. The Interesting Part — Collision Mathematics

Ask them:

"How do we know whether two circles overlap?"

Don't give the formula immediately.

Let them reason.

Distance between centers:

        B
        ●
       / 
      / d
     /
    ●
    A

Distance:

const dx = x2 - x1;
const dy = y2 - y1;

const distance = Math.sqrt(
    dx * dx + dy * dy
);

Two circles overlap if:

distance <= radius1 + radius2

🔥

Now you're teaching:

Math
+
JavaScript
+
DOM
+
CSS
+
visualization

That's a much better learning experience than:

"Here's what querySelector() does."

🔥 27. Force Event Delegation Into Todo

This is important.

Don't let them attach:

button.addEventListener(...)

to every dynamically created button.

Instead:

todoList.addEventListener("click", (event) => {
    // figure out what was clicked
});

For example:

<li>
    Learn DOM
    <button class="delete">X</button>
</li>

Then:

if (event.target.classList.contains("delete")) {
    event.target.parentElement.remove();
}

Now students understand why bubbling and delegation actually matter.

🧠 The "Don't Teach Today" List

I would intentionally avoid going deep into:

window object
prototype chain
DOM prototypes
Document interface internals
Node inheritance hierarchy
MutationObserver
Shadow DOM
Custom Elements
Web Components
Rendering pipeline
Layout/reflow internals

They'll eventually need these concepts, but not for today's objective.

Today's mental model should simply be:

"The browser turns my HTML into a tree. JavaScript can find nodes in that tree, change them, create new ones, remove them, and react to things users do."
