PART 2 — Functions Are Values

Before higher-order functions, establish one extremely important JavaScript fact.

Functions can be stored
function greet() {
  console.log("Hello");
}

const x = greet;

x();

Output:

Hello

Notice:

const x = greet;

NOT:

const x = greet();

Explain:

greet

means:

Give me the function.

greet()

means:

Execute the function.

This distinction becomes extremely important with callbacks.

PART 3 — Functions Can Be Passed Around
function greet(name) {
  console.log("Hello", name);
}

function execute(fn) {
  fn("Abhishek");
}

execute(greet);

Output:

Hello Abhishek

Explain:

execute(greet)

We're passing a function as data.

PART 4 — Higher Order Functions

Now introduce the definition.

A higher-order function is a function that either:

accepts another function as an argument
returns a function
or both.

Example:

function calculate(a, b, operation) {
  return operation(a, b);
}

function add(a, b) {
  return a + b;
}

function multiply(a, b) {
  return a * b;
}

console.log(calculate(5, 3, add));
console.log(calculate(5, 3, multiply));

Output:

8
15

Then:

calculate(5, 3, (a, b) => a - b);

Output:

2

This naturally leads into arrow functions.

PART 5 — Arrow Functions

Start with the normal function:

function add(a, b) {
  return a + b;
}

Convert gradually.

Step 1
const add = function(a, b) {
  return a + b;
};
Step 2
const add = (a, b) => {
  return a + b;
};
Step 3
const add = (a, b) => a + b;

Explain:

If the arrow function has a single expression, JavaScript automatically returns it when braces are omitted.

Parameter shortcuts

One parameter:

const square = x => x * x;

Instead of:

const square = (x) => {
  return x * x;
};

Zero parameters:

const sayHello = () => {
  console.log("Hello");
};

Multiple parameters:

const add = (a, b) => a + b;
Interesting Arrow Function Trap

Put this on screen:

const getUser = () => {
  name: "Rahul"
};

Ask:

What does this return?

Answer:

undefined

Because {} is interpreted as a function body.

To return an object:

const getUser = () => ({
  name: "Rahul"
});

This is an extremely common React/JavaScript syntax pattern.

PART 6 — Callback Functions

Now:

function processUser(name, callback) {
  console.log("Processing", name);
  callback();
}

processUser("Rahul", () => {
  console.log("Done");
});

Explain:

The function passed into another function is called a callback.

Then show:

setTimeout(() => {
  console.log("Hello");
}, 1000);

You've already seen callbacks with timers, so connect it with today's concept.

PART 7 — Array Methods

Now the main section.

Start with:

const numbers = [1, 2, 3, 4, 5];

Explain the three most important methods:

map     → transform
filter  → select
reduce  → accumulate

And also:

forEach → perform an action
find    → find one
some    → does at least one satisfy?
every   → do all satisfy?
includes → does this exist?
PART 8 — map()

Start extremely simple.

const numbers = [1, 2, 3, 4];

const result = numbers.map(x => x * 2);

console.log(result);

Output:

[2, 4, 6, 8]
Mental model

Think:

1 → 2
2 → 4
3 → 6
4 → 8

Every element enters the callback.

Every callback returns the corresponding element of the new array.

Important fact

map() returns a new array.

const numbers = [1, 2, 3];

const result = numbers.map(x => x * 2);

console.log(numbers);
console.log(result);

Output:

[1, 2, 3]
[2, 4, 6]
map() with objects

This is where real-world JavaScript starts becoming recognizable.

const users = [
  { name: "Rahul", age: 20 },
  { name: "Aman", age: 25 },
  { name: "Priya", age: 22 }
];

const names = users.map(user => user.name);

console.log(names);

Output:

["Rahul", "Aman", "Priya"]

Then:

const adults = users.map(user => ({
  name: user.name,
  isAdult: user.age >= 18
}));

Output:

[
  { name: "Rahul", isAdult: true },
  { name: "Aman", isAdult: true },
  { name: "Priya", isAdult: true }
]
PART 9 — filter()
const numbers = [1, 2, 3, 4, 5];

const even = numbers.filter(x => x % 2 === 0);

console.log(even);

Output:

[2, 4]

Mental model:

1 → false → remove
2 → true  → keep
3 → false → remove
4 → true  → keep
5 → false → remove
Important distinction

map:

Change every element.

filter:

Decide which elements survive.

Objects + filter
const users = [
  { name: "A", age: 17 },
  { name: "B", age: 21 },
  { name: "C", age: 30 }
];

const adults = users.filter(user => user.age >= 18);

Output:

[
  { name: "B", age: 21 },
  { name: "C", age: 30 }
]
PART 10 — find()

This is a great comparison.

const users = [
  { id: 1, name: "A" },
  { id: 2, name: "B" },
  { id: 3, name: "C" }
];

const user = users.find(user => user.id === 2);

console.log(user);

Output:

{
  id: 2,
  name: "B"
}
filter

returns:

[object, object]
find

returns:

object

If nothing is found:

undefined
PART 11 — some() and every()

Very useful and frequently overlooked.

const numbers = [2, 4, 6, 8];
some
numbers.some(x => x > 5);

Output:

true

Meaning:

Is there at least one?

every
numbers.every(x => x % 2 === 0);

Output:

true

Meaning:

Do all satisfy the condition?

PART 12 — forEach()
const numbers = [1, 2, 3];

numbers.forEach(x => {
  console.log(x);
});

Output:

1
2
3

Important comparison:

map()

returns a new array.

forEach()

doesn't exist primarily to produce a new array.

Show the classic mistake:

const result = numbers.forEach(x => x * 2);

console.log(result);

Output:

undefined
PART 13 — reduce()

Don't go too deep initially, but students should understand it.

const numbers = [1, 2, 3, 4];

const sum = numbers.reduce((acc, current) => {
  return acc + current;
}, 0);

console.log(sum);

Output:

10

Visualize:

acc    current
0        1       → 1
1        2       → 3
3        3       → 6
6        4       → 10

Then a real example:

const cart = [
  { name: "Laptop", price: 50000 },
  { name: "Mouse", price: 1000 },
  { name: "Keyboard", price: 2000 }
];

const total = cart.reduce(
  (total, item) => total + item.price,
  0
);

Result:

53000

Tell them:

reduce() is powerful, but don't use it just because you can. map, filter, find, etc. often communicate intent more clearly.

PART 14 — Object Access

Now transition to syntax.

const user = {
  name: "Rahul",
  age: 22,
  address: {
    city: "Delhi",
    pincode: 110001
  }
};
Dot notation
user.name
user.age
user.address.city
Bracket notation
user["name"]
user["age"]

Ask:

Why would we ever need brackets?

Dynamic properties.

const key = "name";

console.log(user[key]);

Output:

Rahul

But:

user.key

looks for a property literally called "key".

This distinction is very important.

PART 15 — Destructuring

Now introduce one of the most common modern JS features.

Instead of:

const name = user.name;
const age = user.age;

we can write:

const { name, age } = user;

Now:

console.log(name);
console.log(age);
Rename while destructuring
const {
  name: userName,
  age: userAge
} = user;

Now:

console.log(userName);
console.log(userAge);

Explain:

name      → property
userName  → local variable
Default values
const {
  name,
  country = "India"
} = user;

If country doesn't exist:

country === "India"
Nested destructuring
const user = {
  name: "Rahul",
  address: {
    city: "Delhi",
    pincode: 110001
  }
};

We can do:

const {
  name,
  address: {
    city
  }
} = user;

Now:

console.log(name);
console.log(city);
PART 16 — Destructuring Function Parameters

This is very important for React.

Instead of:

function printUser(user) {
  console.log(user.name);
  console.log(user.age);
}

We can write:

function printUser({ name, age }) {
  console.log(name);
  console.log(age);
}

Then:

printUser({
  name: "Rahul",
  age: 22
});

And now show:

users.map(({ name, age }) => {
  return `${name} is ${age}`;
});

Students will suddenly recognize a lot of React code.

PART 17 — Array Destructuring
const numbers = [10, 20, 30];

const [a, b, c] = numbers;

console.log(a);
console.log(b);
console.log(c);

Output:

10
20
30

Skipping:

const [first, , third] = numbers;

Result:

first = 10
third = 30
Swapping Variables

Cool little fact:

let a = 10;
let b = 20;

[a, b] = [b, a];

console.log(a, b);

Output:

20 10

No temporary variable.

PART 18 — Spread Operator

Introduce:

...

But explain that its meaning depends on context.

Arrays
const a = [1, 2, 3];

const b = [...a, 4, 5];

console.log(b);

Output:

[1, 2, 3, 4, 5]
Copying arrays
const a = [1, 2, 3];

const b = [...a];

console.log(a === b);

Output:

false

Different array.

But remind them:

Spread performs a shallow copy.

Objects
const user = {
  name: "Rahul",
  age: 22
};

const updatedUser = {
  ...user,
  age: 23
};

Output:

{
  name: "Rahul",
  age: 23
}

This is extremely common in React state updates.

PART 19 — Rest Operator

Same syntax:

...

Different meaning.

const [first, ...rest] = [1, 2, 3, 4];

console.log(first);
console.log(rest);

Output:

1
[2, 3, 4]

Function example:

function sum(...numbers) {
  return numbers.reduce((a, b) => a + b, 0);
}

console.log(sum(1, 2, 3, 4));

Output:

10

Tell students:

Spread expands. Rest collects.

PART 20 — Optional Chaining

Extremely useful in real applications.

Given:

const user = {
  name: "Rahul"
};

This can cause problems:

console.log(user.address.city);

Because:

user.address

is undefined.

Instead:

console.log(user.address?.city);

Output:

undefined
Optional function call
user.login?.();

Meaning:

Call login only if it exists.

PART 21 — Nullish Coalescing
const name = null;

const result = name ?? "Guest";

Result:

Guest

Compare:

const name = "";

console.log(name || "Guest");

Output:

Guest

But:

console.log(name ?? "Guest");

Output:

""

Explain:

||

checks for falsy values.

??

checks specifically for:

null
undefined

This is a great interview concept.

PART 22 — Ternary Operator

Instead of:

let message;

if (age >= 18) {
  message = "Adult";
} else {
  message = "Minor";
}

We can write:

const message = age >= 18
  ? "Adult"
  : "Minor";

Very common in React:

{
 isLoggedIn ? <Dashboard /> : <Login />
}
PART 23 — Logical Operators as Values

This is a really interesting JavaScript fact.

console.log("Hello" && "World");

Output:

World

And:

console.log(null && "World");

Output:

null

Because && doesn't necessarily return true/false.

Then:

const isLoggedIn = true;

isLoggedIn && console.log("Dashboard");

Very common React pattern:

{isAdmin && <AdminPanel />}
PART 24 — Object Shorthand

Show:

const name = "Rahul";
const age = 22;

Old:

const user = {
  name: name,
  age: age
};

Modern:

const user = {
  name,
  age
};

Output is identical.

PART 25 — Computed Property Names

Interesting fact:

const key = "name";

const user = {
  [key]: "Rahul"
};

Result:

{
  name: "Rahul"
}

Very useful when dynamically constructing objects.

PART 26 — Object Property Override

This is an excellent output question.

const user = {
  name: "Rahul",
  age: 20
};

const updated = {
  ...user,
  age: 25
};

console.log(updated);

Output:

{
  name: "Rahul",
  age: 25
}

Because later properties override earlier properties.

Now reverse:

const updated = {
  age: 25,
  ...user
};

Output:

{
  age: 20,
  name: "Rahul"
}

This is very important when students start using React state and APIs.

PART 27 — Method Chaining

Now bring everything together.

const users = [
  { name: "A", age: 17 },
  { name: "B", age: 21 },
  { name: "C", age: 25 },
  { name: "D", age: 15 }
];

const result = users
  .filter(user => user.age >= 18)
  .map(user => user.name);

console.log(result);

Output:

["B", "C"]

Explain the pipeline:

users
   ↓
filter
   ↓
[ B, C ]
   ↓
map
   ↓
["B", "C"]
PART 28 — The "Real Code" Challenge

Now give them this:

const products = [
  {
    name: "Laptop",
    price: 80000,
    category: "electronics",
    inStock: true
  },
  {
    name: "Mouse",
    price: 1500,
    category: "electronics",
    inStock: false
  },
  {
    name: "Book",
    price: 500,
    category: "education",
    inStock: true
  },
  {
    name: "Keyboard",
    price: 3000,
    category: "electronics",
    inStock: true
  }
];

Question:

Get names of all in-stock electronics.

First solution:

const result = products
  .filter(product => product.category === "electronics")
  .filter(product => product.inStock)
  .map(product => product.name);

Output:

["Laptop", "Keyboard"]

Now make them improve it.

Destructuring
const result = products
  .filter(({ category }) => category === "electronics")
  .filter(({ inStock }) => inStock)
  .map(({ name }) => name);

Then combine:

const result = products
  .filter(
    ({ category, inStock }) =>
      category === "electronics" && inStock
  )
  .map(({ name }) => name);

This is the moment where they see how several "small" concepts combine into production syntax.

PART 30 — One Important Shallow Copy Trap

Since you've already taught shallow/deep copy, connect it.

const user = {
  name: "Rahul",
  address: {
    city: "Delhi"
  }
};

const copy = {
  ...user
};

copy.address.city = "Mumbai";

console.log(user.address.city);

Output:

Mumbai

Why?

Because:

copy
 ↓
address ─────────┐
                 ↓
              same object

Spread only copied the first level.

PART 31 — map() + Destructuring + Spread

Give them this realistic example:

const users = [
  {
    id: 1,
    name: "Rahul",
    age: 20
  },
  {
    id: 2,
    name: "Priya",
    age: 25
  }

We want to add isAdult.

const updatedUsers = users.map(user => ({

PART 32 — A Syntax Cheat Sheet

At the end, give them this mental map.

Syntax	Meaning
obj.name	Access property
obj[key]	Dynamic property access
const {name} = obj	Object destructuring
const [a,b] = arr	Array destructuring
...arr	Spread
...args	Rest
a => a * 2	Arrow function
x => ({})	Arrow returning object
arr.map()	Transform
arr.filter()	Select
arr.find()	Find one
arr.reduce()	Accumulate
arr.some()	At least one?
arr.every()	All?
arr.forEach()	Perform action
obj?.name	Safe property access
a ?? b	Null/undefined fallback
a ? b : c	Conditional expression
a && b	Execute/use b if a truthy
{name}	Object shorthand
{[key]: value}	Computed property

The teaching philosophy I'd use today

Don't teach this as:

"Today we'll learn 15 JavaScript methods."

Teach it as:

"Today we're learning how to read the JavaScript developers actually write."

The progression should be:

Function
   ↓
Function as a value
   ↓
Callback
   ↓
Higher-order function
   ↓
Arrow function
   ↓

   ↓
Arrays of objects
   ↓
Object access
   ↓
Destructuring
   ↓
Spread / Rest
   ↓
